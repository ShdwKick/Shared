# Общие файлы

Здесь лежит то, что во всех сервисах одинаково. **Единственное место, где это
редактируют** — дальше файлы раскладываются по сервисам механически.

Репозиторий: `github.com/ShdwKick/Shared` (публичный).

Почему рядом с сервисами существуют копии: Docker собирает образ из каталога
сервиса и выйти за его пределы не может — `COPY ../Shared/brand.css` физически
невозможен. Альтернатива была бы тянуть стили по сети с auth-домена, но тогда
чужой сервис перестаёт краситься, когда auth недоступен, и каждая страница ждёт
лишний кросс-доменный запрос ради оформления. Копии оставляют сервисы
самодостаточными, а редактирование — в одном месте.

## Что здесь

| Файл | Что делает | Куда попадает |
|---|---|---|
| `brand.css` | токены сервиса, горящий фон, знак, локап | `assets/` каждого сервиса |
| `brand.js` | расстановка искр | `assets/` каждого сервиса |
| `mark.svg` | эталонный знак, от 24 пикселей | берут вручную при надобности |
| `mark-small.svg` | знак для 16–24 пикселей (вырез дома крупнее) | основа для фавикона сервиса |

Почему знака нет в раскладке: он вставляется в разметку **inline**, иначе
градиент не увидит переменные сервиса и знак уедет в чёрный (см.
`Design/mark.md`). А фавикон у каждого сервиса свой — с вписанными цветами,
потому что в фавиконе CSS-переменные не работают вовсе.

## Раскладка

```bash
node Shared/sync.mjs           # разложить по сервисам
node Shared/sync.mjs --check   # только проверить, что копии не разъехались
```

Копии получают шапку «не редактировать здесь». Правка в `assets/` сервиса уедет
при следующей раскладке — это не досадное свойство, а смысл затеи.

Новый сервис добавляется одной строчкой в списке `TARGETS` внутри `sync.mjs`.

Сравнение идёт с приведением переводов строк к общему виду. На Windows git сам
переводит рабочую копию в CRLF, и побайтовая сверка начинала бы кричать о
расхождении после каждого `clone`, `checkout` или `stash` при полностью
одинаковом содержимом.

## Чтобы не забыть разложить

В каждом репозитории сервиса ставится хук — он не даст закоммитить отставшую копию:

```bash
cp ../Shared/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

Хуки не коммитятся вместе с кодом, поэтому ставить нужно в каждом репозитории и
заново после свежего клона. Если папки `Shared` рядом нет, хук молча
пропускает проверку: человек мог склонировать один сервис, чтобы починить баг,
и про общие стили не знать вовсе.

Проверить в CI нельзя — workflow видит только свой репозиторий, а `Shared`
лежит рядом. Это осознанная цена выбранной схемы: сборка соберёт что угодно,
поэтому следит хук на своей машине.

## Почему это отдельно от Design

`Design/` отвечает на вопрос **почему** (концепция, палитра, правила, причины
решений), `Shared/` — на вопрос **чем** (файлы, которые сервис забирает как
есть). Документы читают люди, файлы забирает скрипт; смешивать их — значит
рано или поздно нечаянно «поправить документацию» в работающем коде.

## Что сюда просится, но пока не переехало

`auth-client.js` и `auth-client-browser.js` — ровно такой же общий код, сейчас
живут в `Auth/client/` и копируются в сервисы руками. Переезд сюда напрашивается,
но задевает деплой (Dockerfile «Финансов», `.dockerignore` в Auth, пример сервиса
и `INTEGRATION.md`), поэтому делать его заодно со стилями я не стал — это
отдельный шаг, который стоит делать с проверкой сборки.
